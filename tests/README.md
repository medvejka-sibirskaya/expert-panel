# Тесты этапа 0 — раскладка (по §15 ТЗ v1.3)

Обязательный набор. Прогон тихим режимом (итог + PASS/FAIL), полные выводы —
`--verbose`. Фикстуры — синтетические (выдуманные секреты и контакты),
реальные материалы и реальный `.env` не используются; данные — во временной
папке, не в боевой `D:\expert-panel\`.

| # | Тест | Что доказывает |
|---|---|---|
| 1 | Секрет в docx/xlsx/pdf обнаруживается | сканер работает по извлечённому тексту контейнерных форматов, а не по бинарному содержимому |
| 2 | PDF-скан без текстового слоя → статус «не проверено на секреты» | честный статус вместо «проверено, находок нет» |
| 3 | Значения секретов/ПД отсутствуют в stdout/stderr/логах | тишина сканера: только O-имя, маркер, тип |
| 4 | Контактные ПД замаскированы в разрешённой копии | контакты маскируются всегда, во всех режимах |
| 5 | Пост-маска: эксперт воспроизвёл email в замечании → пойман в отчёте | маска бьёт по финальным текстам, не только по копиям |
| 6 | До утверждения Preflight в `work\<run_id>\` нет ни одного файла | копии создаются только после выбора режима |
| 7 | Пустые значения настроек → работают дефолты | `env_ignore_empty=True`-поведение (retention_days=90 и др.) |
| 8 | Двойной запуск → отказ по lock | один активный запуск |
| 9 | Lock мёртвого процесса → снятие по подтверждению | восстановление после аварийного завершения |
| 10 | Остатки `work\` от незавершённого запуска → обнаружены, удаление по подтверждению | не молчаливая очистка |
| 11 | Повреждённый хвост журнала → quarantine с repair_id + `journal_repaired` с тем же repair_id, seq восстановлен | восстановление без молчаливой обрезки |
| 12 | Незакрытый перенос (запись в quarantine без события) → повтор только записи события, без повторного переноса | идемпотентность восстановления |
| 13 | Дубль `event_id` → явная ошибка | идемпотентность журнала |
