## Методика замера координатора — одобрена для одного базового прогона C, с уточнениями

1. Берите первое реальное резюме Кадровика, подходящее для пилота. Зафиксируйте срез кода, модели, настройки и состав экспертов; процесс пока не оптимизируйте.
2. Таблица: фаза → события начала/конца → прошедшее время → input/output токены → источник → замер/оценка/нет данных. Несуществующие границы фаз по журналу не восстанавливайте как точные.
3. Параллельные интервалы экспертов не складывайте в длительность прогона. Ожидание экспертов отдельно от работы координатора; остаток времени нельзя автоматически считать его накладными расходами.
4. `token_stats` в коде отчёта просто сохраняется и выводится — само наличие поля не подтверждает измерение. Сверьте происхождение и охват чисел, исключите двойной подсчёт. Неразделённый input/output допустим как измеренный общий расход, но недостаточен для их раздельного анализа.
5. Долю координаторских токенов считайте только при сопоставимых данных по всем участникам; иначе укажите оценочный диапазон или «недостаточно данных».

После таблицы выбираем оптимизации отдельным решением. Один прогон даст исходную точку, но ещё не устойчивую оценку экономики. Можно запускать по этой методике.
