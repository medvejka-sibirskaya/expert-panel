# Expert Panel — изменение ТЗ: «редактура» как функция комиссии (v1.3 → v1.4)

Привет, Жора. Возвращаюсь с новой темой — это не отчёт о прогоне, а предложение изменить ТЗ. Медвежка хочет, чтобы комиссия не только выдавала замечания, но и **автоматически отдавала исправленную версию документа**. Кода не писала, ничего не меняла — сначала твоё ревью и утверждение Медвежки.

=== 1. ЧТО ХОЧЕТ МЕДВЕЖКА ===

Комиссия должна уметь выдавать отредактированный документ. Две границы, заданные Медвежкой:

- **MVP (это изменение):** исправленная версия — в **md**, контакты остаются **масками** ([ТЕЛЕФОН]/[EMAIL]). Владелец документа вставляет контакты сам.
- **Конечная цель (отдельный этап, НЕ в этой версии):** полный цикл — «загрузила документ → пришёл новый исправленный файл + отдельный файл пояснений, что и почему изменено». Требует записи в docx и подстановки реальных контактов — это я фиксирую только как направление, чтобы не размывать границу MVP.

=== 2. КОНФЛИКТ С ТЕКУЩИМИ ПРИНЦИПАМИ ===

Редактура задевает формулировки ТЗ:

- §1: «Вне MVP: … автоматические исправления».
- §2.4: «Комиссия ничего не изменяет в проверяемом материале».
- §2.11 и §11.5: «на диск — только маскированные копии; немаскированный текст — только в памяти».
- §13: «ни один скрипт не пишет в проверяемые материалы».

Ключевой момент проектирования: **в MVP-варианте ни один из принципов секретного контура нарушать не надо.** Редактура — это по-прежнему маскированная копия, просто отредактированная. Немаскированного файла на диске не появляется, исходник не трогается.

=== 3. ПРОЕКТИРУЕМЫЙ КОНТУР (MVP) ===

1. **Опциональный этап после судьи.** Включается отдельной строкой Preflight («нужна редактура? да + место выдачи + границы»). Не каждая проверка требует редактуры.
2. **Корректор — новая роль `expert-editor`.** Read-only, как остальные (Read/Glob/Grep) — инструменты записи агенту не даём. Получает на вход: маскированную копию `O1.md` + перечень **принятых** замечаний (id, location, recommendation). Возвращает отредактированный текст + перечень правок (id → что изменено).
3. **Запись делает координатор** (не агент): `edited_O1.md` в `work\<run_id>\`.
4. **Границы правки:** корректор правит **только по принятым замечаниям** + необходимая связность (согласование форм, согласование родов), без самовольных содержательных правок. Каждая правка привязана к id замечания — редактура проверяема, как и сами замечания.
5. **Итог:** `edited_O1.md` (маскированный) + раздел в MD-отчёте «Внесённые правки» (id → что изменено). Исходник не изменён (контроль по хешам, как в §15). Retention — как у отчётов.

Почему read-only + возврат текста, а не Edit/Write корректору: не даём агенту инструменты записи, сохраняем единообразие «агенты комиссии read-only», а единственная запись — координатор. Для резюме (небольшой документ) возврат полного текста дёшев; для больших документов это ограничение — честно помечу.

=== 4. ЦЕЛЕВАЯ КАРТИНА (после MVP, отдельным согласованием) ===

Полный цикл: входной документ (docx/pdf) → исправленный файл с реальными контактами + файл пояснений. Потребует: (а) запись docx (python-docx, форматирование — упрощённое или с сохранением стилей); (б) **уникальные маски** контактов ([ТЕЛЕФОН#1]…) + обратимое соответствие маска↔значение, чтобы подставить реальные; (в) исключение в §11 — появится немаскированный итоговый ПД-файл (локально, retention). Это отдельный этап с новым Preflight — не сейчас.

=== 5. ИЗМЕНЕНИЯ ТЗ (конкретно) ===

| Пункт | Что меняем |
|---|---|
| §1 | «автоматические исправления» → «автоматические исправления исходника — вне MVP; редактура (исправленная маскированная копия) — опциональный этап» |
| §2.4 | «не изменяет проверяемый материал» → «не изменяет исходный материал; может создавать отредактированную маскированную копию (опционально)» |
| §3 | + `expert-editor.md` (корректор) |
| §4 | + строка роли корректора + модель |
| §5 | + шаг «Редактура (опционально)» после судьи |
| §6 | + пункт Preflight: нужна ли редактура, место выдачи, границы |
| §9 | + опциональный артефакт `edited_*.md` + раздел «Внесённые правки» |
| §15 | + тесты: исходник не изменён; редактура маскирована; корректор не выходит за границы; правка привязана к id |

6.4. Границы правки «только по принятым замечаниям + связность, без самовольных» — ок? Это ключевое, чтобы редактура не стала неконтролируемой переделкой.
