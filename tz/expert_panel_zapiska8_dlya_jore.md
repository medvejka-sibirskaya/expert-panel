# Expert Panel — v1.5 (предложение): автономный агент, адаптивная комиссия, компактные брифы

Привет, Жора. Это следующий шаг после v1.4 (редактура). Медвежка пересмотрела, как комиссия должна работать в боевом режиме: не конвейер, которым она управляет вручную (сама запускает агентов, выбирает исполнителей, ведёт промежуточные этапы), а **автономный агент**: она даёт документ и параметры → утверждает Preflight → получает результат. Черновик правок в SKILL.md уже внесён — прошу отревьюить до синхронизации ТЗ.

## Что предлагается

**1. Автономный прогон.** Единственная точка согласования — Preflight. После утверждения координатор сам, без промежуточных подтверждений: определяет тип документа → назначает состав по таблице → раздаёт брифы → параллельная волна → сводка → судья → (при редактуре) корректор → отчёт. Медвежка не запускает агентов, не выбирает исполнителей, не управляет промежуточными этапами. Границы не расширяются: состав/модели/этапы/режим без нового согласования менять нельзя (это уже было в ТЗ — теперь дополнено положительной формулировкой автономности).

**2. Адаптивная комиссия.** Не гонять все роли без нужды — обязательный состав по типу документа:

| Тип документа | Обязательные роли | Опциональные роли |
|---|---|---|
| Резюме (пилот) | facts + domain (HR) + critic + style | — (полный состав, отработан) |
| Промпт | facts + critic | style |
| ТЗ | domain (предметник области) + facts + critic | style |
| КП (коммерческое) | critic + style + domain (предметник) | facts |

Судья expert-judge — всегда; корректор expert-editor — только при включённой редактуре. Итоговый состав фиксируется в Preflight п.4 (координатор предлагает по таблице, отклонения — с обоснованием); после утверждения менять его без нового согласования нельзя.

**3. Компактные брифы.** Бриф эксперта = роль + зона ответственности (что проверяет именно этот эксперт) + манифест (точные пути + O-имена + контрольные якоря) + формат замечаний. Координатор даёт эксперту только релевантный его зоне материал, не перегружает бриф чужими областями и не пересказывает чужие заключения.

**4. Чистый edited.** `edited_O*.md` — готовый к использованию текст **без служебных маркеров привязки `[абзац N]`** (маркеры остаются только в разрешённых копиях `work\` и в локациях/цитатах замечаний). Маски контактов `[ТЕЛЕФОН]`/`[EMAIL]` сохраняются: это маскированная копия, а не исходник с реальными контактами.

## Ключевой принцип

Автономность ≠ снятие границ и ≠ обход согласования запуска. Запуск — по-прежнему только после утверждения Preflight; молчание/«посмотрим» ≠ разрешение. Оптимизация не трогает механизмы независимости экспертов, доказательности замечаний, обработки секретов/ПД, журнала и проверки diff при редактуре — меняется только способ управления координатором внутри уже утверждённого сценария. Новой архитектуры не вводится — оптимизируется существующий Expert Panel.

## Вопросы к тебе

1. Согласен с автономным прогоном после Preflight (единственная точка согласования)?
2. Адаптивная таблица состава — ок? Не ослабляет ли она качество для промпт / ТЗ / КП?
3. Компактные брифы без потери независимости и полноты (аудитор фактов по-прежнему видит весь документ, у остальных — чёткая зона) — ок?
4. `edited` без маркеров `[абзац N]` — согласен?

Если замечаний нет — синхронизирую ТЗ в v1.5 и фиксирую решение в истории изменений.
