# Expert Panel — v1.4: упрощение редакторского процесса (уточнение к ответу №6)

Привет, Жора. Это не отчёт о прогоне, а уточнение к v1.4 после твоего ответа №6. Медвежка посмотрела на согласованный вариант и решила упростить редакторский процесс — откатиться от «второго варианта» (ручной выбор ID после сводки) к автоматическому. Код не писала, реализацию не трогала — только поправила ТЗ, жду твоего подтверждения.

Что изменилось относительно ответа №6:

1. **Выбор ID — отменён.** По твоему финальному вопросу Медвежка сначала выбрала «второй вариант» (выбор конкретных ID после сводки), теперь передумала: редактура запускается автоматически, если включена в Preflight, и корректор исправляет **все замечания с типом «подтверждённая»** (confirmed). Отдельного подтверждения каждого замечания и ручного выбора ID нет. Это ровно твой «первый вариант» — проще и ближе к целевому полному циклу.

2. **Два файла на выходе.** Вместо раздела «Внесённые правки» внутри MD-отчёта — два отдельных артефакта в `reports\<run_id>\`:
   - `edited_O*.md` — полная исправленная маскированная копия;
   - `changes_O*.md` — пояснения: что исправлено, почему, основание (какое замечание), какие подтверждённые не удалось исправить и почему.
   В MD-отчёте — только факт «редактура выполнена» и ссылки на оба файла; в JSON — поле `editor_stage{status, fixed[], unfixed[]}`.

3. **Правила правки (§5а) без изменений по существу:** только «подтверждённая», минимальность, запрет новых фактов, сохранение неопределённости. Субъективные/вероятные/предположения не правятся — при необходимости лишь упоминаются в `changes` как оставленные без изменения.

4. **Остальное из твоего ответа №6 сохранено:** отдельная роль `expert-editor` (read-only, полная `glm-5.3:cloud`), запись только координатором, пост-маска до записи, проверка diff (нет новых фактов / выходов за границы → не публикуем), исходник и разрешённая копия не меняются, вердикт исходной проверки не меняется, полный цикл (DOCX + реальные контакты) — вне v1.4.
