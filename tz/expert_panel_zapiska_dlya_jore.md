Спецификация Expert Panel v0.1 принята за основу — Клоди сверила её со своим
аудитом hiring-panel, противоречий не нашла. Границы уточнили, зафиксировано:

1. Назначение сужено: MVP — только документы (промпты, ТЗ, КП, резюме).
   Проверка кода/проектов/скиллов — за пределами MVP.
2. Первый пилот — резюме (в связке с нашим агентом по резюме).
3. Хеш-цепочка JSONL отложена, в MVP — простая проверка целостности.
4. Имя точки входа: /expert-panel (внутренний список навыков уже назван
   «Библиотекарь», обязателен разделитель: Библиотекарь = routing,
   Комиссия = глубокое ревью).
5. Guard от выдумок: скрипт проверяет только форматы и вычислимое (числа,
   даты, схемы); свободные утверждения сверяет отдельный эксперт-аудитор
   фактов по цитатам из исходника — скриптовая проверка чисел не ловит
   семантические выдумки.

Ответы Клоди по §16 (предварительные, до окончательного ТЗ сверит по
документации Claude Code):
- Независимость субагентов: реальна — свежий контекст на каждого,
  запуск параллельной волной в одном сообщении (проверено и в
  hiring-panel, и в практике Клоди).
- Ограничение доступа экспертов: частично — кастомные определения агентов
  с узким набором инструментов; запрет конкретных путей — сверит.
- Точная статистика токенов субагентов: НЕ гарантирована — КЛОДИ даст
  оценки по размеру брифов/ответов; спецификация это уже допускает
  («оценка диапазоном», «оценочные нельзя выдавать за фактические»).
- Остановка сверх лимита: надёжная точка контроля — на стыках фаз,
  механическая остановка агента — внутри фазы.
- Форматы: md/txt/docx/pdf/xlsx покрыты; нечитаемое — фиксируется как
  ограничение (§6).
- Обнаружение секретов: только эвристика, не гарантирует полное покрытие —
  отражаем в документации (§12).

Следующий шаг: Клоди пишет ТЗ для реализации на полной модели, затем
сверка §16 по документации и только потом код. Новые функции не добавляем.
