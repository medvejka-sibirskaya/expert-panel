# Expert Panel — «Экспертная комиссия» [АРХИВ]

**Статус: проект закрыт как продукт 06.11.2026.** Текущая разработка не ведётся;
репозиторий оставлен как архив истории, приёмочных материалов и решений.
Активная жизнь проекта продолжается в двух местах:

- **универсальные скрипты** — библиотека `D:\claude_utils\` (см. «Что уносим с собой»);
- **новый проект «комиссия профильных отделов»** — планируемая переделка

## Что это было

Скилл Claude Code `/expert-panel`: независимая экспертная комиссия для проверки
документов (резюме, ТЗ, КП, промпты). Полный конвейер: инвентаризация → скан
секретов и контактных ПД → маскирование → Preflight (единственная точка
согласования) → параллельная волна экспертов → механическая сверка цитат →
судья → опциональная редактура (корректор делает исправленную копию с
плейсхолдерами `[ЗАПОЛНИТЬ: …]` вместо выдуманных фактов) → отчёт MD+JSON →
append-only журнал с lock/quarantine.

## Что сделано (всё работает, 43 теста passed)

- ТЗ v1.0→v1.5: 5 версий спецификации, все по раундам внешнего ревью («Жора»).
- 7 скриптов + 6 агентов (read-only): волна 4 ролей, судья, корректор.
- `verify_evidence.py`: строгая сверка цитат (локация ±0 строк), CRLF,
  многочастные цитаты; `check_numbers.py`: числа/даты/стаж.
- Безопасность: маскирование всегда, сканер значений не выводит нигде,
  пост-маска финальных текстов, retention 90 дней с удалением по подтверждению.
- Журнал: run_id/event_id/seq, идемпотентность, lock с проверкой живости,
  quarantine-repair повреждённого хвоста.
- Редактура: edited_O*.md + changes_O*.md, без служебных маркеров, исходник
  не трогается.
- Интеграционные прогоны: R3 (нашла инверсию O-привязок), R4 (закрыла), C —
  реальная проверка резюме с замером по методике Жоры.
- Коммит `1359783` — переработка ролей под «профильные отделы» (domain —
  параметризуемая профессия, judge — руководитель согласования); движок при
  этом не менялся.

## Почему закрыто — честно

**Вердикт владельца (Медвежка, 06.11.2026):** «работа ради работы». Три
конкурентных контекста, в которых комиссия проиграла:

1. **Базовая линия оказалась не «один агент», а один промпт.** «Один промпт
   в ChatGPT: документ + описание вакансии/ссылка на закон — пара минут,
   пара центов — и готовый ответ». Против этого комиссия не может выиграть:
   30+ минут исполнения сессией-координатором и ~192 685 токенов агентов
   на одно резюме (замер прогона C; расход координатора замерить было нечем).
2. **Прирост качества не доказан.** Комиссия читает один документ шестью
   ролями без внешних источников — замечания неотличимы от сильного
   одиночного отзыва; сравнение «комиссия vs один агент» так и не было
   проведено и утратило актуальность вместе с решением.
3. **Совокупность инженерных решений не проверялась на нужность в ходе
   работы.** Всё обосновывалось результатами предыдущего раунда ревью самой
   себя. Урок зафиксирован: **эксперимент прежде проектирования; если
   решение работает — не усложняем.**

## Что уносим с собой

- **Библиотека `D:\claude_utils\`** — шесть живых, оттестированных утилит:
  - `extract_text` — извлечение текста (docx/xlsx/pdf/md/txt) с маркерами привязки;
  - `scan_secrets` — скан и маскирование секретов и контактных ПД;
  - `verify_evidence` — механическая проверка цитат LLM-заключений
    (анти-галлюцинация);
  - `check_numbers` — вычислимая проверка чисел/дат;
  - `compare_reports` — сравнение отчётов;
  - `journal` — append-only журнал запусков с идемпотентностью и repair.
  Тесты и фикстуры перенесены (38 passed).
- **Концепция комиссий, проверенная на ошибках.** Мультиагентная проверка
  имеет смысл там, где у проверяющих **непересекающиеся компетенции и/или
  разные источники** (модель согласования договоров подразделениями
  компании). Эта идея — основа нового проекта «комиссия профильных
  отделов», который открывается отдельно.
- **Опыт организации**: 12 раундов независимого ревью, методика замеров
  экономики, правила честных отчётов («доказательство инструментом, а не
  пересказом»), шаблон журнала запуска. Всё это — в `tz\` и истории git.
